## 🌿 Git с нуля

**Git** — программа на вашем компьютере, которая хранит историю изменений кода.
**GitHub** — сайт, куда эта история загружается, чтобы её увидел преподаватель.

Что требуется от вас по итогу:

1. свой **приватный** репозиторий на GitHub с копией этих заданий;
2. на каждое задание — **отдельная ветка** и **Pull Request**;
3. в PR автоматически запускаются тесты (CI), я смотрю результат в интерфейсе GitHub.

### Пять слов, которые нужно понимать

| Слово | Что это |
|---|---|
| Репозиторий | Папка проекта вместе с историей всех изменений |
| Коммит | Сохранённое состояние кода + подпись, что вы сделали |
| Ветка | Отдельная линия работы. Своя ветка на каждое задание, чтобы не мешать друг другу |
| Push | Отправить свои коммиты на GitHub |
| Pull Request (PR) | Заявка «проверь мою ветку». Именно её я и проверяю |

### Шаг 1. Установить Git

**Windows** — скачайте установщик с [git-scm.com/download/win](https://git-scm.com/download/win) и пройдите установку со значениями по умолчанию.
Все команды ниже выполняйте в программе **Git Bash** (появится в меню «Пуск»), а не в cmd.

**macOS** — git почти наверняка уже установлен. Откройте Terminal и выполните `git --version`:
если git не найден, macOS сама предложит его доустановить — согласитесь.
Либо поставьте руками через [Homebrew](https://brew.sh): `brew install git`.

**Linux**:

```bash
sudo apt update && sudo apt install git   # Ubuntu / Debian
sudo dnf install git                      # Fedora
sudo pacman -S git                        # Arch
```

Проверка — команда должна напечатать версию:

```bash
git --version
```

### Шаг 2. Представиться

Git подписывает каждый коммит вашим именем. Выполните один раз:

```bash
git config --global user.name "Ivan Ivanov"
git config --global user.email "ivan@example.com"
```

Почту указывайте ту же, что и на GitHub.

### Шаг 3. Настроить доступ к GitHub

Обычный пароль от GitHub в терминале **не работает**. Нужно настроить доступ один раз —
выберите любой из двух способов.

#### Вариант А (рекомендуемый): SSH-ключ

SSH-ключ — это пара файлов: приватный лежит у вас на компьютере, публичный вы отдаёте GitHub.
Настраивается один раз и работает во всех репозиториях.

**1. Создайте ключ** (Windows — в Git Bash, macOS/Linux — в терминале):

```bash
ssh-keygen -t ed25519 -C "ivan@example.com"
```

На все три вопроса просто нажмите **Enter** (путь по умолчанию, пустой пароль).

**2. Скопируйте публичный ключ** в буфер обмена:

```bash
clip < ~/.ssh/id_ed25519.pub        # Windows (Git Bash)
pbcopy < ~/.ssh/id_ed25519.pub      # macOS
cat ~/.ssh/id_ed25519.pub           # Linux — выделите и скопируйте вывод
```

⚠️ Копируется файл именно с расширением **`.pub`**. Файл без `.pub` — приватный ключ,
его никому показывать нельзя.

**3. Добавьте ключ на GitHub:**
[github.com/settings/keys](https://github.com/settings/keys) → **New SSH key** →
Title — любое (например `Мой ноутбук`), Key — вставьте скопированное → **Add SSH key**.

**4. Проверьте:**

```bash
ssh -T git@github.com
```

На вопрос `Are you sure you want to continue connecting?` ответьте `yes`.
Успех выглядит так:

```
Hi ВАШ_ЛОГИН! You've successfully authenticated, but GitHub does not provide shell access.
```

Дальше используйте SSH-адреса репозиториев — они начинаются с `git@github.com:`.

#### Вариант Б: GitHub CLI

Если с ключами не получилось — поставьте GitHub CLI и залогиньтесь через браузер:

```bash
winget install --id GitHub.cli   # Windows
brew install gh                  # macOS
sudo apt install gh              # Ubuntu (или см. cli.github.com)

gh auth login
```

В диалоге выбирайте: `GitHub.com` → `HTTPS` → `Yes` (authenticate Git) → `Login with a web browser`.
Дальше используйте HTTPS-адреса репозиториев — они начинаются с `https://github.com/`.

### Шаг 4. Сделать свою приватную копию

1. Откройте [github.com/new](https://github.com/new): задайте имя (например `python-homework-2025`), выберите **Private**, ничего не добавляйте (ни README, ни .gitignore) → **Create repository**.
2. В терминале выполните:

```bash
# скачать исходные задания себе на компьютер
git clone https://github.com/mistandok/students_homework.git
cd students_homework

# отвязать от учебного репозитория
git remote remove origin
```

3. Привязать к своему репозиторию. Выполните **только одну** строку — ту, что
соответствует выбранному в шаге 3 способу входа:

```bash
# вариант А, SSH-ключ:
git remote add origin git@github.com:ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
```

```bash
# вариант Б, GitHub CLI:
git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
```

Готовый адрес можно скопировать на странице своего репозитория: зелёная кнопка **Code** → вкладка **SSH** или **HTTPS**.

4. Залить код в свой приватный репозиторий:

```bash
git push -u origin main
```

> ⚠️ **Этот push делается до того, как вы начали что-либо решать.**
> В ветке `main` должен лежать чистый исходный код заданий — от него будут считаться ваши изменения.
> Если залить туда уже готовые решения, в Pull Request'ах не будет видно, что именно вы написали, и проверить их не получится.
>
> Дальше **в `main` не коммитим вообще**: каждое решение — отдельная ветка и отдельный PR (шаг 5).
> Один PR = одно задание: так я вижу изменения по каждому заданию отдельно и CI показывает результат именно по нему.

5. В своём репозитории: **Settings → Collaborators → Add people → `mistandok`**. Без этого я не увижу ваш код.

### Шаг 5. Цикл работы над одним заданием

Эти шаги повторяются для каждого задания. Пример — задание `1_strings`:

```bash
# 1. вернуться на главную ветку и забрать актуальное состояние
git checkout main
git pull

# 2. создать ветку под задание и переключиться на неё
git checkout -b task/1_strings

# 3. ... пишете код, запускаете тесты: uv run pytest 1_strings/ -v ...

# 4. посмотреть, что изменилось
git status

# 5. сохранить изменения в истории
git add .
git commit -m "Решение заданий по строкам"

# 6. отправить ветку на GitHub
git push -u origin task/1_strings
```

Затем на GitHub:

1. Откройте свой репозиторий — появится жёлтая плашка **«Compare & pull request»**, нажмите её.
   (Если плашки нет: вкладка **Pull requests → New pull request**, base `main`, compare — ваша ветка.)
2. Напишите понятный заголовок, например `Задание 1_strings`.
3. В правой панели **Reviewers** добавьте `mistandok` → **Create pull request**.
4. Внизу PR появятся проверки CI. Дождитесь зелёных галочек — красный крестик значит, что тесты или линтер падают.

Нужно что-то исправить (по замечаниям или из-за красного CI) — правьте код **в той же ветке**:

```bash
git add .
git commit -m "Исправил замечания"
git push
```

PR обновится сам, CI перезапустится. Новый PR создавать не нужно.

Следующее задание — снова с шага 1: `git checkout main`, `git pull`, новая ветка.

### Шпаргалка

| Команда | Что делает |
|---|---|
| `git status` | Что изменено и на какой вы ветке |
| `git branch` | Список веток, звёздочка — текущая |
| `git checkout main` | Переключиться на ветку `main` |
| `git checkout -b task/2_dicts` | Создать новую ветку и перейти в неё |
| `git add .` | Отметить все изменения для коммита |
| `git commit -m "текст"` | Сохранить изменения в историю |
| `git push` | Отправить коммиты на GitHub |
| `git pull` | Забрать изменения с GitHub |
| `git log --oneline` | История коммитов кратким списком |
| `git diff` | Показать, что именно вы поменяли в файлах |
| `git remote -v` | Показать адрес репозитория на GitHub |

### Если что-то пошло не так

**`Author identity unknown` / `Please tell me who you are`** — не выполнен шаг 2.

**Просит логин и пароль, пароль не подходит** — не выполнен шаг 3. Либо настройте SSH-ключ, либо `gh auth login`.

**`Permission denied (publickey)`** — GitHub не знает вашего ключа. Проверьте `ssh -T git@github.com`
и что содержимое `~/.ssh/id_ed25519.pub` добавлено в [github.com/settings/keys](https://github.com/settings/keys).

**`Repository not found` при push** — обычно адрес `origin` не совпадает со способом входа
(SSH-ключ, а адрес `https://...`, или наоборот). Посмотрите `git remote -v` и при необходимости замените:

```bash
git remote set-url origin git@github.com:ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
```

**`nothing to commit`, а изменения есть** — вы забыли `git add .` или сохранили файл не в той папке.

**`Everything up-to-date`, но на GitHub изменений нет** — вы не сделали `git commit` перед `git push`.

**Случайно начали работать в `main` (ещё не коммитили)** — просто создайте ветку, изменения перенесутся с вами:

```bash
git checkout -b task/1_strings
```

**`! [rejected] ... non-fast-forward`** — на GitHub есть коммиты, которых нет у вас:

```bash
git pull --rebase
git push
```

**Конфликт при `git pull`** — git пометит проблемные места в файле символами `<<<<<<<`, `=======`, `>>>>>>>`. Оставьте нужный вариант кода, удалите эти маркеры, затем:

```bash
git add .
git commit -m "Разрешил конфликт"
git push
```

**Всё сломалось, хочется начать заново** — ваш код на GitHub никуда не денется. Можно склонировать репозиторий в новую папку и продолжить там.
